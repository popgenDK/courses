Estimating the site frequency spectrum (SFS) from low depth NGS data¶

The site frequency spectrum is one of the most used summaries of genetic variation. For a sample of diploid individuals you go through the sites in the genome, count how many derived alleles the sample carries at each site, and tabulate how often each count occurs. The result is a vector

where is the proportion of sites with exactly derived alleles out of the alleles in the sample. Because it is a proportion, .

Almost everything we estimate from allele frequencies is a function of the SFS: nucleotide diversity, Watterson's , Tajima's D, , demographic history and tests for selection. So if we can estimate the SFS well, we can estimate all of those well.

The problem. With low depth NGS data we do not know the genotypes, so we do not know the allele counts either. The obvious thing to do - call the genotypes and count - turns out to be badly biased. In this exercise we will see that bias with our own eyes, and then fix it with a method that never calls a genotype: it works directly on the genotype likelihoods and uses an EM algorithm, exactly the way ANGSD/realSFS does it.

Learning objectives

  • Know what the SFS is and why it has categories
  • See why calling genotypes at low depth gives a biased SFS
  • Understand the sample allele frequency likelihood (SAF),
  • Be able to write up the likelihood of the SFS and the E- and M-step of the EM algorithm
  • Estimate the SFS from genotype likelihoods and compare it to the truth

Everything below is simulated, which is the nice thing about this exercise: we know the true answer and can check how close each method gets.

The data. Simulated in the notebook: allele frequencies from a beta distribution, genotypes for 10 individuals at 100,000 sites, then sequencing reads on top of those genotypes. Because the truth is known at every step, the estimated SFS can be compared with the real one.

1. Simulating the data¶

We build the data in four steps, each of which mimics one step of a real study

  1. a true allele frequency for each site in the population
  2. true genotypes for individuals, drawn under Hardy-Weinberg
  3. sequencing reads for each individual with a given depth and error rate
  4. genotype likelihoods computed from those reads - this is what we would get from real data

We then throw away everything except the genotype likelihoods (step 4), estimate the SFS from them, and compare with the SFS we can calculate from the true genotypes (step 2).

The population allele frequencies¶

The frequencies of the sites in a genome are not uniform: most variable sites are rare. A convenient distribution with that shape is the beta distribution, and we use . This plays the role that the true demographic history would play for real data - it is what generates the shape of the SFS.

2. Simulating NGS data¶

Now we pretend we sequenced these individuals. For each individual and site

  • the depth is drawn from a Poisson distribution, , where is the average depth of the individual
  • each of the reads samples one of the individual's two alleles at random
  • with probability the read shows the other allele instead (a sequencing error)

To keep it simple we pretend there are only two possible bases instead of the usual four. The probability that a single read is derived is then

genotype
0
1
2

and the genotype likelihood is the binomial probability of seeing the observed number of derived reads out of reads

where is the number of reads carrying the derived allele. Note that the genotype likelihood is not a probability of the genotype - it is the probability of the data for each of the three possible genotypes.

In [6]:
# Simulate genotype likelihoods from genotypes.
#
# Input is a n-by-m matrix of genotypes, output is a n-list length of
# 3-by-m matrices.
sim_gl <- function(gt, error = 0.01, mean_depth = 2, min_depth = 0) {
  n <- nrow(gt)
  m <- ncol(gt)
  e <- c(error, 0.5, 1 - error)
  depths <- pmax(rpois(n * m, mean_depth), min_depth)
  probs <- e[gt + 1]
  alts <- rbinom(n * m, depths, probs)
  gl <- sapply(e, dbinom, x = alts, size = depths)
  lapply(seq(n), function(i) t(gl[seq(i, nrow(gl), n),]))
}

3. Estimating the SFS from genotype likelihoods¶

Instead of calling genotypes we treat the allele count as a hidden variable and estimate the SFS by maximum likelihood. The SFS itself is the parameter: is the probability that a random site has derived alleles, so it doubles as the prior on the hidden state, .

This is the same shape as every other EM problem in this course: a sum over a hidden state, with one factor that depends on the data and one that is the parameter. Estimating is done in two steps

  1. compute for every site and every - the SAF
  2. run an EM algorithm on those numbers

The nice thing is that step 1 only has to be done once: the SAF does not depend on , so it is computed up front and the EM then only touches a matrix.

Step 1: the sample allele frequency likelihood (SAF)¶

is the sequencing data of all individuals at site . We need the probability of that data given that the sample carries exactly derived alleles

In words: sum over every combination of individual genotypes that adds up to derived alleles, and for each combination multiply the genotype likelihoods together (the individuals are independent given their genotypes).

Written like that the sum is hopeless - there are genotype combinations, which for is already 59049 per site and for 100 individuals is more than the number of atoms in the universe. The trick is to add the individuals one at a time: if you know the distribution of the allele count over the first individuals, adding individual only requires combining it with that individual's three genotype likelihoods. That turns into something proportional to , and it is what the loop in calc_saf below does.

In [10]:
# Input is a list of 3-by-m matrices, output is a 2*n+1-by-m matrix.
calc_saf <- function(gl) {
  n <- length(gl)
  m <- unique(sapply(gl, ncol))
  saf <- matrix(0, nrow = 2 * n + 1, ncol = m)
  c <- choose(2, 0:2)
  saf[1:3, ] <- c * gl[[1]]
  for (i in 2:n) {
    # Loop invariant: after ith iteration, first 2 * i + 1 rows of SAF
    # would contain SAF for first i individuals if divided by
    # choose(2 * i, 0:(2 * i)))
        g <- gl[[i]]
        for (j in (2 * i - 1):1) {
            saf[j + 2,] <- colSums(saf[(j + 2):j,] * c * g)
        }
    saf[2,] <- saf[2,] * g[1,] + saf[1,] * 2 * g[2,]
    saf[1,] <- saf[1,] * g[1,]
  }
  saf / choose(2 * n, 0:(2 * n))
}

Step 2: the EM algorithm¶

With the SAF in hand the EM algorithm is short. The hidden state is the allele count and the parameter is the SFS itself.

E-step - the posterior probability of each allele count at each site, by Bayes' formula

M-step - the new SFS is the average posterior over all sites

The denominator is just , because the posterior of each site sums to one. In other words: count each site as a fraction of a site in every category, instead of forcing it into the single category of its called genotype. That is exactly what the genotype calling approach could not do.

In [12]:
# Run an E-step.
#
# Input is SFS and precalculated (2 * n + 1)-by-m SAF matrix,
# output is (2 * n + 1)-by-m matrix of posterior allele count probabilities.
e_step <- function(sfs, saf) {
  post <- sfs * saf
  sweep(post, 2, colSums(post), `/`)
}
# Run an M-step.
#
# Input is (2 * n + 1)-by-m matrix of posterior allele count probabilities,
# output is new SFS.
m_step <- function(post) {
  new <- rowSums(post)
  new / sum(new)
}
# Runs EM for fixed number of iterations.
em <- function(saf, iterations = 50) {

  sfs <- rep(1 / nrow(saf), nrow(saf))
  for (i in seq(iterations)) {
    sfs <- m_step(e_step(sfs, saf))
  }
  sfs
}


em_sfs <- em(saf, iterations = 50)
barplot(em_sfs,xlab="Number of derived alleles",ylab="fraction of sites",col=3,main="SFS from GL (EM algo)")
