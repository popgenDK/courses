Genotype imputation from low depth sequencing data¶

We have 30 European (CEU) samples sequenced to low depth - a few reads per site - on a 3 Mb piece of chromosome 20. At that depth a single read can never tell you whether an individual is homozygous or heterozygous, so calling each genotype on its own is a losing game.

Imputation gets around this by sharing information between sites and between individuals: nearby alleles are inherited together on haplotypes, so a site with no reads at all can still be filled in from the haplotype it sits on. This exercise is about the three different ways of doing that and how much each one helps.

What you will do¶

  1. Prepare the input: genotype likelihoods from the bam files with ANGSD.
  2. Look at the file formats imputation uses, going in and coming out.
  3. Impute with three different strategies (Beagle 4.1, QUILT2, Beagle 5.5).
  4. Compare all of them against a truth data set - the same individuals sequenced to high depth - using the unimputed ANGSD genotype calls as the baseline.
  5. Bonus: impute a mother, and think about her fetus, from simulated NIPT data.

Short follow-up questions come after most code cells. They are the point of the exercise - the commands themselves are only a few lines each.

This exercise starts from genotype likelihoods and goes straight to imputation. If you want the SNP and genotype calling step in detail - bcftools and ANGSD, SNP discovery, and what a called genotype at 1x is worth - that is the companion exercise genotype_calling_and_imputation_human.ipynb.

The software we will use¶

ANGSD only calls - it uses the reads of one individual plus the estimated allele frequency, and nothing else. The other three impute: they model the data as a mosaic of haplotypes and therefore also use the sites around the site of interest.

Tool Input Works on low depth data? Needs a reference panel? Output
ANGSD BAM For genotype likelihoods yes, for genotype calls no No (uses the estimated allele frequency as prior) genotype likelihoods, allele frequencies, called genotypes
Beagle 4.1 (gl=) genotype likelihoods (VCF/BCF) Yes Optional - here we use no panel, the 30 study samples impute each other phased genotypes, GP, dosage
QUILT2 BAM Yes - it is designed for 0.1-1x data Yes (required) phased genotypes, GP, DS, HD
Beagle 5.5 (gt=) called genotypes (e.g. a SNP chip) No - it needs confident genotypes as input Yes (required) phased genotypes at all panel sites, GP

Beagle 4.1 and QUILT2 read uncertain data (likelihoods or reads), while Beagle 5.5 reads hard genotype calls. Keep that distinction in mind - it explains most of the differences you will see at the end.

Genotype likelihoods with ANGSD¶

Beagle 4.1 needs genotype likelihoods, not genotype calls, so we make them with ANGSD. A genotype likelihood is p(reads | genotype) for each of the three genotypes, which keeps the uncertainty that a single read cannot resolve.

We ask ANGSD for both the likelihoods (-doGlf 2, and a BCF via -doBcf 1) and its own genotype calls (-doGeno 2 -doPost 2). The calls are not the input to anything below - we keep them as the no imputation baseline to compare against at the end.

3. The file formats imputation uses¶

Going in: the reference panel and the genetic map¶

Reference panel. IMPUTE format hap and legend files with the reference haplotypes. They can be made from a haplotype VCF with bcftools convert --haplegendsample, or by hand. The haplotype file is gzipped with no header and no rownames, one row per SNP and one column per reference haplotype, space separated, with values 0 (ref) and 1 (alt). The legend file is gzipped with a header, giving position (the physical position in 1-based coordinates), a0 for the reference allele and a1 for the alternate allele. An optional sample file, and a file of samples to exclude, are useful for changing who is in the panel.

Genetic map. Three white-space delimited columns: position (1-based), the genetic rate in cM/Mbp, and the cumulative genetic map in cM.

Bams. A bamlist, one row per sample, holding the path to the bam.

(Optional) truth data. A phasefile and a posfile, useful for measuring performance. The phasefile has a header row naming each sample, matching the bam, and is tab separated with one subject per column, 0 for ref and 1 for alt, the two alleles separated by a vertical bar, e.g. 0|0 or 0|1. It therefore has one row more than the posfile. The posfile has no header, one row per SNP, and four tab separated columns: chromosome, physical position (sorted ascending), reference base and alternate base, with the bases capitalised.

The output VCF fields¶

Imputation output keeps the uncertainty, which is the whole point. Per sample you get:

  • GT - phased genotypes, where each allele is the rounded per-haplotype posterior probability (HD below)
  • GP - genotype posteriors: the posterior probabilities of the three genotypes given the data
  • DS - diploid dosage: the posterior expected number of alternative alleles (a number between 0 and 2)
  • HD - haploid dosages: the per-haplotype posterior probability of the alternative allele

Note that in QUILT the genotype posteriors (GP) and dosages (DS) come from the main Gibbs sampling, while the phasing (GT and HD) comes from an extra phasing Gibbs sample. They can therefore be slightly inconsistent with each other; if you need consistency you can build GP and DS from HD.

4. Imputation¶

An imputation program does not treat the sites independently. It models each individual's two chromosomes as a mosaic of haplotypes (a hidden Markov model, where switching between haplotypes is a recombination event and the genetic map tells it how likely a switch is). Once you know which haplotype an individual is copying at a position, you also know which allele to expect - even at a site with no reads at all.

The haplotypes to copy from can come from

  • the study samples themselves (Beagle 4.1 below: the 30 study samples impute each other), or
  • an external reference panel of phased high quality haplotypes (QUILT2 and Beagle 5.5 below).

We will run three variations on this theme and then compare them all against the truth.

4b. QUILT2 - straight from BAM files with a reference panel¶

QUILT2 skips the genotype calling step entirely: it reads the reads and a reference panel and returns imputed, phased genotypes. This is currently the best approach for very low depth sequencing data.

Running all 30 individuals takes about 20 minutes, so we run one individual as a demonstration (2 minutes, most of it spent preparing the reference panel) and then use a precomputed result for all 30 individuals in the comparison below.

5. Comparing the approaches against the truth¶

We now have four sets of genotypes for (mostly) the same individuals and sites:

name how it was made
angsd genotype calling from the posterior, no imputation - the baseline
beagle4gl imputation from genotype likelihoods, no reference panel
quilt2 imputation from bams with a reference panel
beagle5gl imputation of SNP chip genotypes with a reference panel

The truth set is the same individuals sequenced to high depth. We read all the files, match sites and individuals to the truth, and compute

  • the missing genotype rate, and
  • the concordance rate: the fraction of genotypes identical to the truth. Missing genotypes make that ambiguous, so we report it both ways - counting a missing genotype as wrong, and ignoring missing genotypes altogether.

# helper: pull out a matrix (e.g. genotypes) from one vcf, with the rows (sites)
# and columns (individuals) matched to the truth set
find_match <- function(vcf_in, vcf_truth, name="tool", data_type="gt"){
    if(!all(vcf_truth$samples %in% vcf_in$samples)){stop("samples doesn't match")}
    true_pos_match <- match(vcf_truth$pos, vcf_in$pos)
    vcf_in[[data_type]][true_pos_match, match(vcf_truth$samples, vcf_in$samples)]
}

estimate_gt_tools <- function(gt_mat_list = list(), gt_true_mat = matrix(), keep = c()){
    if(!all(lapply(gt_mat_list, nrow) == nrow(gt_true_mat))){stop("SNP count doesn't match")}
    if(!all(lapply(gt_mat_list, ncol) == ncol(gt_true_mat))){stop("Sample count doesn't match")}
    if(length(keep) == 0){
        keep <- rep(TRUE, nrow(gt_true_mat))
    }

    # missing genotypes counted as discordant
    res <- sapply(gt_mat_list, function(x){
        x[is.na(x)] <- -1
        mean(gt_true_mat[keep, ] == x[keep, ], na.rm=TRUE)})

    # fraction of missing genotypes
    resMis <- sapply(gt_mat_list, function(x)
        mean(is.na(x[keep, ]), na.rm=TRUE))

    # missing genotypes ignored
    resNA <- sapply(gt_mat_list, function(x)
        mean(gt_true_mat[keep, ] == x[keep, ], na.rm=TRUE))

    cat("Missing genotype rate:\n")
    print(round(resMis, 4))
    cat("\nConcordance rate assuming missing is discordant:\n")
    print(round(res, 4))
    cat("\nConcordance rate when ignoring missing genotypes:\n")
    print(round(resNA, 4))
    invisible(list(missing=resMis, concordance=res, concordance_nonmissing=resNA))
}

6. Bonus: QUILT2 on NIPT data¶

In non-invasive prenatal testing (NIPT) one sequences cell-free DNA from the blood of a pregnant woman. The sample is a mixture: most of the DNA comes from the mother, and a fraction f (the fetal fraction, often 5-30%) comes from the fetus. So a "1x NIPT sample" is really a low depth mixture of two related genomes.

If you treat it as one ordinary diploid sample you will get the mother roughly right and the fetus not at all. QUILT2 has a dedicated nipt mode which models three haplotypes (the mother's two, plus the paternally inherited fetal one) together with the fetal fraction.

The extra bam file we left out of the bamlist is a simulated NIPT sample at 1x with a fetal fraction of 0.3. The mother is NA12828. We impute it in both modes and compare - reusing the prepared reference from the QUILT2 run above, so this is fast.
